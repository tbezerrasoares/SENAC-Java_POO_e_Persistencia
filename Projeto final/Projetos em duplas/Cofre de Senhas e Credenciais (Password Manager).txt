Cofre de Senhas e Credenciais (Password Manager)
1. Visão Geral
Em um cenário de TI onde profissionais gerenciam dezenas de acessos a diferentes plataformas, a segurança e a organização das credenciais são críticas. O objetivo deste projeto é desenvolver um Cofre de Senhas centralizado. A aplicação deve permitir o armazenamento seguro de usuários, senhas e URLs/IPs de servidores, sites e bancos de dados, garantindo que informações sensíveis não fiquem expostas em planilhas ou arquivos de texto simples.
2. Objetivos de Aprendizado e Aplicação (POO)
O projeto foca na organização de diferentes tipos de dados sob uma estrutura comum, utilizando conceitos avançados do Módulo 2:
Classes Abstratas: Implementar uma classe abstrata base (ex: Credencial) que contenha atributos comuns como usuario e senha. A partir dela, criar subclasses específicas como CredencialWeb (com campo URL), CredencialServidor (com campo IP/Protocolo) e CredencialBancoDados (com campo Porta/SGBD).
Contratos de Comportamento: Utilizar métodos abstratos para forçar que cada tipo de credencial valide seus dados de forma específica (ex: validar se uma URL começa com "https" ou se um IP é válido).
Proteção de Dados (Encapsulamento): Aplicar o modificador private rigorosamente, garantindo que a senha nunca seja acessada diretamente sem passar por métodos de tratamento.
3. Requisitos de Persistência e Segurança (JDBC)
Este projeto introduz um desafio extra de segurança lógica na camada de persistência:
Persistência com JDBC: O sistema deve realizar o CRUD completo das credenciais em um banco de dados SQL.
Simulação de Criptografia: Antes de enviar a senha para o banco de dados (via INSERT ou UPDATE), a lógica Java deve aplicar uma transformação nos dados (ex: inversão de string, Base64 ou uma cifra simples) para garantir que, se o banco for invadido, as senhas não estejam em texto claro.
Tratamento de Exceções: Gerenciar falhas de conexão e erros de SQL para evitar a exposição de detalhes técnicos do banco ao usuário final.
4. Interface Gráfica e UX (JavaFX)
A interface deve prezar pela simplicidade e agilidade, conforme os conceitos do Módulo 3:
Validação em Tempo Real: Utilizar eventos de teclado ou foco para validar se os campos obrigatórios estão preenchidos enquanto o usuário digita.
Formulário Dinâmico: Criar uma interface que se adapte ao tipo de credencial selecionado (ex: mostrar campo "URL" para Web e esconder para "Servidor").
Segurança Visual: Implementar campos de senha (PasswordField) que ocultam os caracteres durante a digitação na interface.
5. Entregas Esperadas
Ao final a dupla deverá apresentar:
Arquitetura de Classes: Demonstração da classe abstrata e suas especializações.
Demonstração de Segurança: Mostrar como a senha aparece no banco de dados (criptografada) versus como ela aparece na aplicação (descriptografada).
Software Funcional: Cadastro e consulta de diferentes tipos de credenciais integrados ao banco de dados.
